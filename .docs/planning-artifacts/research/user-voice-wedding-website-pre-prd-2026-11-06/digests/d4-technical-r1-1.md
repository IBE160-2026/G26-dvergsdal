### Q5. Concurrency ("last save wins" vs optimistic)

## NFR implications (your synthesis — what the PRD should require, stack-neutral)

1. **Guest link token:** generated with a CSPRNG and at least 128 bits of entropy (e.g. 22+ base64url chars). It must not contain names or other personal data. Each household gets its own token, and admins can regenerate it, which immediately invalidates the old one.
2. **No state change on GET.** Opening a personal link only shows the household and the form. Saving the RSVP is always a POST with CSRF protection. This protects against link scanners and preview fetches.
3. **Token leakage:** pages reached through a token send `Referrer-Policy: no-referrer` and are excluded from search engines (noindex). Token attempts are rate-limited, and unknown tokens get a generic "link not valid" page. Consider swapping the URL token for a cookie session on first visit.
4. **Token storage:** storing tokens hashed is recommended defence in depth, but OWASP does not state it explicitly. This is a PRD decision. Note the trade-off: with hashed storage, admins cannot re-display a link and must regenerate it instead.
5. **Admin passwords:** hashed with Argon2id (OWASP minimum m=19 MiB, t=2, p=1), or scrypt or bcrypt (cost ≥10) as fallbacks. Plaintext or reversible storage is never allowed.
6. **Admin sessions:** server-side sessions in `HttpOnly`, `Secure` (in production) and `SameSite=Lax/Strict` cookies. Regenerate the session ID on login. Idle timeout 15–30 min, absolute timeout ≤8 h. Logout invalidates the session on the server. Login is rate-limited (e.g. 5 attempts per minute per account+IP). There is no public registration, and admins come from seed or setup.
7. **CSRF protection** on every state-changing form, using the framework's built-in mechanism.
8. **Email:** sending goes through an abstraction with a development backend that needs no key (console, file or local catcher). The provider is chosen through environment variables, and `.env.example` contains no real secrets.
9. **Clone-and-run:** one documented command sequence covers setup, migrations, seeding (with fictional guests and a test admin) and start. The database needs no external server in the course version. Seeding has to be an explicit, documented step, because some tools no longer seed automatically (Prisma v7).
10. **Concurrency:** every editable record stores `updated_at` and `updated_by`, and the UI shows "last updated by X at Y". The PRD should decide between accepting last-save-wins with visible attribution, and optimistic locking with a version column, where a conflict message appears instead of silent overwrite.
11. **Data residency (2027):** the hosting and email provider must keep personal data in the EU/EEA. Check where account data and logs are stored, not just the sending region (see Resend).

## Trade-offs to decide in architecture

- **SQLite vs PostgreSQL.** SQLite needs zero setup and is a single file, which suits about 70 guests and 4 admins (one writer at a time is fine). Postgres matches many hosted offerings, but the examiner would need Docker or a local install. Some free hosted Postgres is temporary (Render: 30 days). SQLite in production needs a persistent volume (e.g. Fly volumes) or a VPS.
- **Batteries-included vs assemble-your-own.** Django provides an admin, auth, sessions, CSRF, forms, migrations, an email console backend and a test runner, but its admin is meant for internal use, not a custom dashboard. Laravel provides auth through Fortify with rate limiting, but needs PHP, Composer and npm, which means more prerequisites. JS stacks (Next.js/SvelteKit/Express plus Prisma/Drizzle) need auth, CSRF and admin to be put together separately. Of those, only Prisma was checked in this round.
- **Token storage: hashed vs plaintext.** Hashed storage is safer if the DB leaks. Plaintext lets admins copy and re-send a household's link.
- **Last-save-wins plus attribution vs optimistic locking.** The first is simpler. The second prevents silent overwrite but needs conflict UX.
- **Email provider (2027).** Resend has a generous free tier but stores account data in the US. Postmark's free tier is tiny (100/month). Brevo is EU-based (France) with 300/day free, but this round did not verify its residency from a primary page.
- **Hosting.** A VPS (Hetzner, about €6/month, EU, full control, ops burden) vs a PaaS (Fly: no free tier, about $2–8/month; Render: free tier sleeps, free Postgres expires).
